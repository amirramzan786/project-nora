# Project N.O.R.A. — collaborative development instructions

## Mandatory shared kickoff — before every task

Before editing code, designing anything, running a material migration or selecting tooling, read and apply these canonical shared guides when access is authorised:
- [Development Kickoff](https://github.com/amirramzan786/amirdesigns/blob/main/docs/development-kickoff.md)
- [Shared Design & Development Toolkit](https://github.com/amirramzan786/amirdesigns/blob/main/docs/ai-development-toolkit.md)

They live in the **private** AmirDesigns repository. If unavailable in this working environment, say so at the beginning and apply the embedded summary below. Never claim to have read them unless you have.

**Our default method:** understand the task and inspect existing source/docs/roadmap/priority board → consider existing tools, design resources and relevant external inspiration → brainstorm meaningful concepts and alternatives with Amir → recommend a direction and discuss/agree choices → sketch or preview where helpful → implement after alignment → review/iterate together → verify and document.

**Before substantial new work:** offer up to 3 specific concepts/approaches with trade-offs and your recommendation, including the option of using existing patterns. Consider the shared toolkit: Anime.js v4, Lucide, PhotoSwipe, Playwright, Bencho, UI Skills, plus relevant project-native tools. Use resources only when compatible, maintainable, secure, performant and accessible; don't add them merely because they are in the registry. For significant new design, UX, architecture or feature decisions, discuss material choices with Amir *before* locking in an unapproved direction. Concept visuals or runnable previews are useful where warranted.

**Scope and pace:** keep a brief kickoff even for simple changes. For urgent fixes and regressions, prioritise the fix; for a clearly approved autonomous work plan, proceed without repeated questions. Do not turn minor implementation details into approval bottlenecks. When a genuine new decision changes brand, product, security, data, cost or production, surface it. Respect this repository's own approved direction, design documents, code and tests over generic examples.

**Quality and handoff:** preserve working journeys, approved visuals, privacy/security, accessibility and performance; aim for excellent UX, developer experience and agent experience. Inspect actual desktop/mobile experiences where relevant, verify appropriate tests, and report precise outcomes and outstanding limitations. Record project decisions here and reusable discoveries in the shared toolkit. Do not claim another repo, Plane or deployment was updated unless confirmed.
